1) CHAT MESSAGE REACTIONS
Your existing chat message update rule should be expanded so a signed-in participant can update ONLY the reactions field on a message. Keep the existing owner-only update rule for normal message edits.

Inside:
match /chats/{chatId} {
  match /messages/{messageId} {
    allow update: if signedIn()
      && exists(/databases/$(database)/documents/users/$(request.auth.uid)/chatsList/$(chatId))
      && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['reactions']);
  }
}

2) FRIEND LUDO / GAME CENTER
Add:

match /games/{gameId} {
  allow read: if signedIn()
    && (resource.data.hostUid == request.auth.uid || resource.data.guestUid == request.auth.uid);

  allow create: if signedIn()
    && request.resource.data.gameType == 'ludo'
    && request.resource.data.hostUid == request.auth.uid;

  allow update: if signedIn()
    && (resource.data.hostUid == request.auth.uid || resource.data.guestUid == request.auth.uid)
    && (
      resource.data.hostUid == request.auth.uid
      || request.resource.data.guestUid == request.auth.uid
      || request.resource.data.guestUid == resource.data.guestUid
    );

  allow delete: if signedIn() && resource.data.hostUid == request.auth.uid;
}

NOTES:
- 2048 and Stack Tower are local games and do not require Firestore.
- Friend Ludo uses /games/{gameId} for realtime state.
- Ludo room joining uses the 6-character room code as the /games/{gameId} document ID, so no composite index is required.
- Keep your final catch-all deny rule at the bottom of the Firestore rules.
